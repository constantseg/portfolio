Réveiller un poste depuis la console Active Directory

Wake-on-LAN au clic droit dans « Utilisateurs et ordinateurs Active Directory », par script PowerShell.

Objectif
Ajouter une entrée « Wake On LAN » au menu clic droit des ordinateurs dans la console ADUC, pour allumer un poste à distance avant une intervention ou une mise à jour.
Version 1
L'adresse MAC est lue dans les baux du serveur DHCP. En service.
Version 2
L'adresse MAC est lue dans l'inventaire GLPI par son API REST. En cours (février 2026).

1. Fonctionnement

  1. Le technicien fait un clic droit sur un ordinateur dans ADUC → Wake On LAN.
  2. La console lance l'exécutable et lui passe, en argument, le chemin LDAP de l'objet (LDAP://CN=PC-01,OU=…).
  3. Le script en extrait le nom du poste (CN=…), puis trouve son adresse MAC :
    • version 1 : résolution DNS du nom → adresse IP → bail sur le serveur DHCP → adresse MAC ;
    • version 2 : recherche du poste dans GLPI → ports réseau → adresse MAC.
  4. Il envoie le « paquet magique » (6 octets FF puis 16 fois l'adresse MAC) en broadcast UDP, port 9.
  5. Tout se fait sans fenêtre, sauf en cas d'erreur. Lancé sans argument, le programme ouvre une petite fenêtre pour saisir un nom de poste.
# extrait du script : récupérer le nom du poste passé par ADUC
foreach ($arg in [Environment]::GetCommandLineArgs()) {
    if ($arg -match "LDAP://.*CN=([^,]+)") { $TargetName = $matches[1]; break }
}
$IP  = (Resolve-DnsName -Name $TargetName -Type A | Select-Object -First 1).IPAddress
$Session = New-PSSession -ComputerName $ServeurDHCP      # bail lu sur le serveur DHCP
$MAC = Invoke-Command -Session $Session -ArgumentList $IP -ScriptBlock {
    param($IP_Cible) (Get-DhcpServerv4Lease -IPAddress $IP_Cible).ClientId
}

2. Préparer l'exécutable

  1. Adapter les variables en haut du script : nom du serveur DHCP (version 1) ou URL de l'API et jetons GLPI (version 2).
  2. Convertir le script en .exe (PS1 To Exe / Bat To Exe Converter, sans console, mode STA pour la fenêtre).
  3. Le copier sur un partage caché lisible par les seuls administrateurs : \\<serveur-admin>\WakeOnLan$\WakeOnLan.exe.

3. Version 2 : préparer GLPI

  1. Configuration → Générale → API : activer l'API REST, la connexion par identifiants et par jeton externe. Noter l'URL de l'API.
  2. Ajouter un client API nommé WakeOnLan et copier son App-Token.
  3. Créer un utilisateur dédié, avec la seule lecture sur les ordinateurs et le réseau (toutes entités, récursif), et générer son jeton personnel (User-Token).

Les jetons GLPI sont écrits dans le script, donc dans l'exécutable. Le compte doit rester en lecture seule et le partage réservé aux administrateurs.

4. Ajouter l'entrée au menu clic droit (ADSI Edit)

Droits nécessaires : Administrateurs de l'entreprise. La modification concerne toute la forêt.

  1. Sur un contrôleur de domaine, lancer adsiedit.msc.
  2. Clic droit sur Modification ADSI → Connexion… → point de connexion Configuration.
  3. Aller dans CN=Configuration,DC=<domaine> → CN=DisplaySpecifiers → CN=40C (console en français) ou CN=409 (anglais). Faire les deux si les deux langues sont utilisées.
  4. Propriétés de l'objet CN=computer-Display → attribut adminContextMenu → ajouter :
2,Wake On LAN,\\<serveur-admin>\WakeOnLan$\WakeOnLan.exe

5. Vérifier

  • Rouvrir la console ADUC : l'entrée apparaît au clic droit sur un ordinateur.
  • Éteindre un poste de test (Wake-on-LAN activé dans le BIOS/UEFI et sur la carte réseau), puis le réveiller depuis la console.

Le paquet magique est un broadcast : il ne traverse pas les routeurs. Pour un poste d'un autre VLAN, il faut envoyer depuis ce VLAN ou autoriser le broadcast dirigé sur le routeur.
