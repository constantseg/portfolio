Rappel : les bases de Docker

Images, conteneurs, volumes, les commandes à connaître et comment lire un fichier Compose.

Cette fiche est destinée aux collègues qui interviennent sur le serveur Docker sans l'administrer tous les jours. Portainer fait l'essentiel à la souris ; ces notions servent quand il faut comprendre ou dépanner.

1. Trois notions

NotionCe que c'estÀ retenir
ImageLe modèle figé d'une application (par exemple PostgreSQL ou Semaphore), en lecture seule.On ne modifie jamais une image, on en change la version.
ConteneurUne image en train de tourner. On peut lancer plusieurs conteneurs à partir de la même image.Un conteneur est jetable : tout ce qui est écrit dedans disparaît quand il est recréé.
VolumeUn dossier du serveur branché dans le conteneur.Les données (bases, configuration) vivent dans les volumes et survivent au conteneur.

2. Les commandes utiles

CommandeUsage
docker psConteneurs en cours d'exécution, leurs noms et leurs ports.
docker ps -aTous les conteneurs, y compris arrêtés ou plantés.
docker logs <nom>Journal du conteneur : le premier réflexe quand un service ne démarre pas. -f pour suivre en direct.
docker exec -it <nom> shOuvrir un shell dans le conteneur (bash si l'image le contient).
docker restart <nom>Redémarrer un conteneur figé.
docker volume lsLister les volumes ; ils sont stockés dans /var/lib/docker/volumes/.

3. Pourquoi Docker Compose

Sans Compose, chaque conteneur se lance avec une longue commande :

docker run -d --name glpi_db -p 3306:3306 -e MYSQL_ROOT_PASSWORD=... -v glpi_db:/var/lib/mysql mysql

Illisible, et une faute de frappe suffit à casser le service. Avec Compose, la même chose est écrite une fois dans docker-compose.yml, versionnée dans Gitea, et Docker l'applique d'un coup.

4. Lire un fichier Compose

services:
  uptime-kuma:                       # nom du service
    image: louislam/uptime-kuma:2    # image et version
    restart: always                  # redémarre après un reboot ou un plantage
    ports:
      - "3001:3001"                  # port du serveur : port du conteneur
    environment:
      TZ: Europe/Paris               # réglages ; les mots de passe via ${VARIABLE}
    volumes:
      - kuma_data:/app/data          # volume : dossier dans le conteneur

volumes:
  kuma_data:
Mot-cléRôle
servicesLa liste des conteneurs à lancer.
imageLe programme à utiliser, avec sa version.
ports"3001:3001" = le port 3001 du serveur est relié au port 3001 du conteneur.
environmentLes réglages passés à l'application.
volumesOù sont gardées les données qui doivent survivre au conteneur.

Sur notre serveur, on ne lance pas docker compose up à la main : on modifie le fichier dans Gitea et Portainer redéploie (voir « Relier Gitea et Portainer »).
