Relier Gitea et Portainer

Un seul fichier Compose versionné dans Gitea, redéployé par Portainer à chaque modification.

Objectif
Décrire tous les conteneurs du serveur dans un seul docker-compose.yml, stocké dans Gitea. Portainer lit ce fichier et redéploie les conteneurs modifiés dès qu'un commit est poussé.
Prérequis
Partie 1 (Docker et Portainer installés) et un serveur Gitea en service.

1. Côté Gitea : dépôt et jeton

  1. Créer un dépôt privé containers-docker et y placer le fichier docker-compose.yml.
  2. Noter l'URL du dépôt : http://<IP_SRV_GITEA>:3000/<compte>/containers-docker.
  3. Le dépôt étant privé, Portainer a besoin d'un jeton : Paramètres du profil → Applications → Gérer les jetons d'accès. Créer un jeton nommé Portainer avec uniquement la lecture des dépôts.
  4. Copier le jeton tout de suite : Gitea ne l'affiche qu'une fois.

2. Côté Portainer : créer la stack depuis Git

  1. Environnement local → Stacks → Add stack.
  2. Nom : serveur-production. Build method : Repository.
ChampValeur
Repository URLURL du dépôt containers-docker
Repository referencerefs/heads/main
Compose pathdocker-compose.yml
Authenticationactivée : nom d'utilisateur Gitea + jeton créé à l'étape 1

3. Mises à jour automatiques par webhook

  1. Dans la même page, activer Automatic updates et choisir Webhook. Portainer affiche une URL unique : la copier.
  2. Dans Gitea : dépôt → Paramètres → Webhooks → Ajouter un webhook → Gitea, coller l'URL, déclencheur « push ».
  3. Revenir dans Portainer et cliquer sur Deploy the stack.

À partir de là, toute modification se fait dans le fichier du dépôt, jamais à la main sur le serveur. Un commit sur main déclenche le webhook, Portainer récupère le fichier et ne recrée que les conteneurs modifiés.

Pour forcer le redéploiement complet : Stacks → serveur-production → Pull and redeploy.

4. Les mots de passe hors du dépôt

Le fichier Compose est versionné : aucun mot de passe ne doit y être écrit en clair. On utilise des variables :

environment:
  POSTGRES_PASSWORD: ${MDP_ANSIBLE_BDD}

La valeur est saisie uniquement dans Portainer : Stacks → serveur-production → Environment variables → Add an environment variable (nom de la variable dans name, mot de passe dans value).

5. Vérifier

  • Modifier un détail du fichier dans Gitea (un commentaire suffit) et pousser.
  • Dans Gitea, onglet du webhook : la dernière livraison doit être en vert (code 200/204).
  • Dans Portainer, la stack affiche le nouveau commit et l'heure du redéploiement.

Bonnes pratiques retenues

  • Un bloc par service, séparé par un commentaire (# === Semaphore ===).
  • Les volumes nommés sont déclarés dans la section volumes: en bas du fichier.
  • Les images ont une version fixée (semaphoreui/semaphore:v2.17.33) : une mise à jour est un commit, donc réversible.
