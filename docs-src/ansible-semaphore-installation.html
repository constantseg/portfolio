Procédure · sauvegarde des switchs

Installer Semaphore et Ansible sous Docker

Service dans le Compose, image avec Paramiko, clé SSH, dépôt Gitea, inventaire, tâche planifiée.

Objectif
Sauvegarder chaque nuit la configuration des switchs Aruba et Cisco dans un dépôt Git, avec une interface web (Semaphore) pour lancer, planifier et consulter les exécutions d'Ansible.
Prérequis
Serveur Docker et Portainer (parties 1 et 2), serveur Gitea.
Dépôts Gitea
containers-docker (fichier Compose) et backups-switchs-ansible (playbook, inventaire, sauvegardes).

1. Image Semaphore avec Paramiko

Les modules réseau d'Ansible se connectent aux switchs en SSH avec Paramiko, absent de l'image officielle. Dans le dépôt containers-docker, créer ansible/Dockerfile :

FROM semaphoreui/semaphore:v2.17.33
USER root
RUN apk add --no-cache py3-paramiko py3-pip
USER 1001

2. Ajouter le service au fichier Compose

Dans docker-compose.yml du dépôt containers-docker, ajouter le bloc suivant. Les mots de passe sont des variables renseignées dans Portainer (Stacks → serveur-production → Environment variables).

# ======================================================
# = Semaphore Ansible (sauvegarde auto des switchs)    =
# ======================================================
  ansible_db:
    container_name: ansible_db
    image: postgres:14-alpine
    restart: always
    environment:
      POSTGRES_USER: semaphore
      POSTGRES_PASSWORD: ${MDP_ANSIBLE_BDD}
      POSTGRES_DB: semaphore
    volumes:
      - ansible_db:/var/lib/postgresql/data

  ansible_app:
    container_name: ansible_app
    build: ansible/.                       # utilise le Dockerfile ci-dessus
    image: semaphoreui/semaphore:v2.17.33  # changer la version = mettre à jour
    restart: always
    ports:
      - "8080:3000"
    environment:
      SEMAPHORE_DB_DIALECT: postgres
      SEMAPHORE_DB_HOST: ansible_db
      SEMAPHORE_DB_PORT: 5432
      SEMAPHORE_DB_USER: semaphore
      SEMAPHORE_DB_PASS: ${MDP_ANSIBLE_BDD}
      SEMAPHORE_DB: semaphore
      SEMAPHORE_PLAYBOOK_PATH: /tmp/semaphore/
      SEMAPHORE_ADMIN: admin
      SEMAPHORE_ADMIN_NAME: admin
      SEMAPHORE_ADMIN_EMAIL: admin@serveur.local
      SEMAPHORE_ADMIN_PASSWORD: ${MDP_ANSIBLE_ADMIN}
      SEMAPHORE_ACCESS_KEY_ENCRYPTION: ${SEMAPHORE_KEY}
    volumes:
      - /etc/timezone:/etc/timezone:ro
      - /etc/localtime:/etc/localtime:ro
      - ansible_ssh_keys:/tmp/ssh_keys:ro
    depends_on:
      - ansible_db

# section volumes: en bas du fichier
volumes:
  ansible_db:
  ansible_ssh_keys:

SEMAPHORE_ACCESS_KEY_ENCRYPTION chiffre les secrets stockés par Semaphore. On le génère une fois (head -c32 /dev/urandom | base64), on le range dans le KeePass et on ne le change plus : sans lui, les clés enregistrées dans Semaphore deviennent illisibles.

Pousser le commit : le webhook déclenche Portainer, qui construit l'image et démarre les deux conteneurs.

3. Clé SSH dédiée

Semaphore lit le playbook dans Gitea et y pousse les sauvegardes avec une clé qui ne sert qu'à ça.

ssh-keygen -t ed25519 -C "cle-serveur-ansible" -f ~/.ssh/id_ed25519
sudo mv ~/.ssh/id_ed25519 /var/lib/docker/volumes/serveur-production_ansible_ssh_keys/_data/

La clé publique (id_ed25519.pub) est ajoutée dans Gitea comme clé de déploiement avec écriture sur le seul dépôt backups-switchs-ansible.

4. Configuration dans Semaphore

Ouvrir http://<IP_SRV_DOCKER>:8080 et se connecter avec le compte admin. Créer un projet, puis :

ÉlémentRéglage
Key StoreType SSH Key, coller la clé privée (sudo cat …/_data/id_ed25519). Ajouter aussi les identifiants des switchs (type Login with password).
RepositoryURL ssh://git@<IP_SRV_GITEA>:222/<compte>/backups-switchs-ansible.git, branche main, clé SSH ci-dessus.
InventoryType File, chemin hosts.ini dans le dépôt.
Task TemplatePlaybook backup_switch.yml, inventaire et dépôt ci-dessus.

5. Tester puis planifier

  1. Lancer le modèle avec le bouton Run et suivre la sortie : chaque switch doit être ok ou changed.
  2. Vérifier dans Gitea qu'un commit « Sauvegarde auto du … » est apparu.
  3. Dans le modèle, onglet Schedule : 0 2 * * * (tous les jours à 2 h).

Dépannage

SymptômePiste
paramiko is not installedLe conteneur tourne sur l'image officielle : vérifier la ligne build: et redéployer.
Un switch en UNREACHABLETester ssh depuis le serveur, vérifier identifiants et ansible_network_os (Cisco : ios).
Pas de commit dans GiteaAucune configuration n'a changé (normal), ou clé de déploiement sans droit d'écriture.
