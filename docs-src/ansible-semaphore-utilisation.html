Sauvegarde des switchs : guide d'utilisation

Où trouver les sauvegardes, ajouter ou retirer un switch, lancer la tâche à la main.

La configuration de chaque switch est sauvegardée automatiquement toutes les nuits à 2 h. Ce guide s'adresse aux techniciens qui ont besoin de retrouver une configuration ou de modifier la liste des switchs.

1. Retrouver une sauvegarde

  1. Ouvrir Gitea, dépôt backups-switchs-ansible.
  2. Dossier backups/<site>/ : un fichier <nom-du-switch>.cfg par switch, toujours la dernière version.
  3. Pour une version plus ancienne : ouvrir le fichier puis Historique. Chaque ligne est une nuit où la configuration a changé.
  4. Cliquer sur un commit affiche les lignes ajoutées (vert) et retirées (rouge) : c'est le moyen le plus rapide de savoir ce qui a été modifié sur un switch.

Pas de commit pendant plusieurs jours ? C'est normal : un commit n'est créé que si au moins une configuration a changé.

2. Ajouter ou retirer un switch

La liste des switchs est le fichier hosts.ini du même dépôt, rangé par site :

[Site_C]
SWI-EXEMPLE-01 ansible_host=<IP_DU_SWITCH>
SWI-EXEMPLE-02 ansible_host=<IP_DU_SWITCH> ansible_network_os=ios   # switch Cisco

[Site_C:vars]
nom_site=Site_C
  • Ajouter : une ligne sous le bon site. Pour un Cisco, ajouter ansible_network_os=ios (par défaut : Aruba).
  • Retirer : supprimer la ligne, ou la commenter avec # en indiquant pourquoi (« administrable seulement en web », « ne répond pas »).
  • Enregistrer avec un message de commit clair. La prochaine exécution prend la nouvelle liste.

3. Le playbook

Le fichier backup_switch.yml contient les commandes envoyées aux switchs. On n'y touche que pour changer ce qui est sauvegardé (par défaut show running-config).

4. Lancer une sauvegarde à la main

Utile juste après une intervention sur un switch, pour figer la nouvelle configuration.

  1. Ouvrir Semaphore (lien dans le tableau de bord Homarr du serveur Docker). Identifiants : KeePass du service.
  2. Projet de sauvegarde → Task Templates → bouton Run sur la tâche de sauvegarde.
  3. Suivre la sortie en direct. En fin d'exécution : ok = rien n'a changé, changed = nouvelle version enregistrée.

5. Vérifier que tout tourne

Dans Semaphore, menu History : une exécution par nuit, en vert. Une exécution en rouge indique au moins un switch en échec ; la sortie donne son nom et l'erreur (le plus souvent un switch éteint ou un mot de passe changé).
