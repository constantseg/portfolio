Serveur Docker piloté par Git

Les conteneurs du serveur sont décrits dans un seul fichier versionné dans Gitea. On modifie le fichier, Portainer redéploie.

Le besoin

Plusieurs services devaient tourner sur un même serveur, dont Semaphore pour la sauvegarde des switchs. Je voulais pouvoir les reconstruire à l'identique, savoir qui a changé quoi, et ne pas dépendre de commandes tapées à la main sur le serveur.

[Une phrase sur la situation de départ.]

Gitea, le dépôt de référence

Gitea est une forge Git auto-hébergée, l'équivalent d'un GitHub interne. Il tourne sous Docker avec sa base PostgreSQL, sur son propre serveur. Son port SSH est décalé sur 222 pour ne pas entrer en conflit avec celui du serveur Linux. Il sert à deux choses : garder l'historique des configurations des switchs, et héberger le fichier Compose du serveur Docker.

Portainer, qui applique

Le serveur Docker est une machine Ubuntu Server avec Docker installé depuis le dépôt officiel, et Portainer pour l'administrer. Dans Portainer, la stack serveur-production n'est pas écrite à la main : elle est lue depuis le dépôt containers-docker de Gitea.

  • Un seul fichier décrit tous les conteneurs, séparés par des commentaires, avec leurs volumes déclarés pour que les données survivent à une mise à jour.
  • Un webhook : dès qu'un commit modifie le fichier, Gitea prévient Portainer, qui redéploie les conteneurs modifiés.
  • Des versions d'image fixées (par exemple semaphoreui/semaphore:v2.17.33) : une mise à jour, c'est changer un numéro dans le fichier, et elle reste dans l'historique.

Les points d'attention

  • Aucun mot de passe dans le dépôt. Le fichier contient ${MDP_ANSIBLE_BDD} ; la valeur est déclarée dans les variables d'environnement de la stack, dans Portainer.
  • Un jeton d'accès limité. Portainer lit le dépôt privé avec un jeton Gitea qui n'a que le droit de lecture sur les dépôts.
  • De la documentation pour l'équipe : installation du serveur, liaison Gitea et Portainer, et un rappel des bases de Docker (images, conteneurs, volumes, commandes utiles).
